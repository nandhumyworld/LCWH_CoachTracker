# LCWH (Flary) MVP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the single-coach core loop — a coach builds a daily question set, invites a student, the student completes intake + answers the daily form (with photos), and receives an AI daily report — with the day locking at the student's local 11:59 PM.

**Architecture:** One full-stack Next.js 15 (App Router) app. Server Actions + Route Handlers for mutations, Prisma/Postgres for data, Auth.js (credentials) for 3-role RBAC, a swappable `StorageService` (local disk in MVP) for photos, OpenRouter for AI reports. Scheduled work (auto-submit, photo cleanup) is done by **n8n** POSTing to secret-protected `/api/cron/*` routes — no in-process scheduler. Deployed as a single Docker container on Coolify against a managed Postgres on the same VPS.

**Tech Stack:** Next.js 15.5 · React 19 · TypeScript · Tailwind + shadcn/ui · Prisma 6 · Auth.js v5 · OpenRouter · Docker/Coolify · n8n (cron).

**Spec:** `docs/superpowers/specs/2026-08-17-flary-mvp-design.md` (and `requirements.md`). The plan argues from the spec; executors read both.

## Global Constraints

- **App name (user-facing):** "LifeChanging Wellness Hub" / short "LCWH". Kept as data (`NEXT_PUBLIC_APP_NAME`, `NEXT_PUBLIC_APP_SHORT_NAME`) for future white-labeling (NFR-7). "Flary" is the internal repo name only.
- **Node 20** in Docker (`node:20-alpine`); local dev may use ≥20.
- **Package manager:** npm (lockfile committed).
- **Next build output:** `standalone` (already set in `next.config.ts`) — do not remove.
- **Images never in Postgres:** only `StoredImage` pointer/metadata rows. All file bytes go through `StorageService` (`src/lib/storage`). No direct `fs` calls elsewhere (NFR-2).
- **Images served only via app-authenticated routes** keyed by role/ownership — never a public directory (NFR-4).
- **AI provider is OpenRouter**; the model id is read from the DB (`PromptTemplate.modelId`, editable by Admin) with `OPENROUTER_DEFAULT_MODEL` as fallback — no redeploy to change models (NFR-1).
- **Per-student timezone:** every "day"/cutoff computed in the student's IANA timezone (FR-16). Never use server local time for day boundaries.
- **Cron routes** (`/api/cron/*`) must reject any request without `Authorization: Bearer <CRON_SECRET>` (already enforced by `isAuthorizedCron`).
- **TDD:** write the failing test first, watch it fail, implement minimally, watch it pass, commit. Prefer small focused files.
- **Env access** goes through `src/lib/env.ts` (lazy-validated). Do not read `process.env` directly in feature code (except `NEXT_PUBLIC_*` in client components).

> **Hosted-Postgres migration workflow (IMPORTANT):** the production DB role
> (`authenticator`) cannot create databases, so `prisma migrate dev` fails at
> the shadow-database step (P3014). For every future schema change, generate
> the migration SQL with `migrate diff` and apply it with `migrate deploy`
> (neither needs a shadow DB):
>
> ```bash
> MIG="prisma/migrations/$(date +%Y%m%d%H%M%S)_<name>"
> mkdir -p "$MIG"
> npx prisma migrate diff \
>   --from-schema-datasource prisma/schema.prisma \
>   --to-schema-datamodel prisma/schema.prisma \
>   --script > "$MIG/migration.sql"
> npx prisma migrate deploy
> ```
>
> (For the very first migration we used `--from-empty` instead of
> `--from-schema-datasource`.) Review the generated SQL before deploying. The
> Docker entrypoint runs `migrate deploy` on boot, so committed migration
> files are what ship to production. Seeding uses `npm run db:seed` (loads
> `.env` via `dotenv`).

### Task 1.2: Auth.js credentials config

- [ ] **Step 1:** Create `src/auth.ts` using Auth.js v5 Credentials provider that looks up `User` by email, verifies `passwordHash` via `verifyPassword`, and puts `role` + `id` on the JWT/session. Session strategy `jwt`.

```ts
import NextAuth from "next-auth";
import Credentials from "next-auth/providers/credentials";
import { prisma } from "@/lib/db";
import { verifyPassword } from "@/lib/password";

export const { handlers, auth, signIn, signOut } = NextAuth({
  session: { strategy: "jwt" },
  pages: { signIn: "/login" },
  providers: [
    Credentials({
      credentials: { email: {}, password: {} },
      authorize: async (creds) => {
        const email = String(creds?.email ?? "").toLowerCase();
        const password = String(creds?.password ?? "");
        if (!email || !password) return null;
        const user = await prisma.user.findUnique({ where: { email } });
        if (!user?.passwordHash) return null;
        if (!(await verifyPassword(password, user.passwordHash))) return null;
        return { id: user.id, email: user.email, name: user.name, role: user.role };
      },
    }),
  ],
  callbacks: {
    jwt: ({ token, user }) => {
      if (user) { token.role = (user as { role: string }).role; token.uid = (user as { id: string }).id; }
      return token;
    },
    session: ({ session, token }) => {
      if (session.user) {
        (session.user as { role?: string }).role = token.role as string;
        (session.user as { id?: string }).id = token.uid as string;
      }
      return session;
    },
  },
});
```
